# Next.js 16 — what actually changed

**Read the bundled docs before writing code.** Next ships version-matched
documentation inside the package:

```
node_modules/next/dist/docs/
├── 01-app/01-getting-started/    # images, fonts, css, layouts, metadata
├── 01-app/02-guides/             # upgrading/version-16.md, ai-agents.md, ...
└── 01-app/03-api-reference/
```

Your training data is older than this release. `node_modules/next/dist/docs/01-app/02-guides/upgrading/version-16.md`
is the authoritative list of breaking changes. Check it rather than recalling.

## Async request APIs — breaking

Next 15 made `params` / `searchParams` async with a sync compatibility shim.
**Next 16 removed the shim.** These are async and only async:

- `cookies()`, `headers()`, `draftMode()`
- `params` in `layout`, `page`, `route`, `default`, `opengraph-image`, `icon`
- `searchParams` in `page`

```tsx
// Correct
export default async function Page(props: PageProps<"/products/[slug]">) {
  const { slug } = await props.params
  const query = await props.searchParams
}
```

`PageProps<'/route'>`, `LayoutProps<'/route'>` and `RouteContext<'/route'>` are
globally available type helpers generated by:

```bash
npx next typegen
```

**Run it after adding a route**, or the helper for that path will not exist.

## Images — several breaking changes

- **`images.domains` is removed.** Use `images.remotePatterns` with an explicit
  `hostname` and as narrow a `pathname` as you can manage.
- **`images.qualities` now defaults to `[75]`.** A `quality` prop outside the
  allowed list is silently coerced to the nearest value — `quality={90}` gives
  you 75 unless you widen the config.
- `minimumCacheTTL` and `imageSizes` defaults changed.
- Local images with query strings need `images.localPatterns.search`.
- Local IP optimisation is blocked unless `dangerouslyAllowLocalIP` is set.

```ts
const nextConfig: NextConfig = {
  images: {
    remotePatterns: [
      { protocol: "https", hostname: "images.unsplash.com", pathname: "/photo-**" },
    ],
    qualities: [75, 90],
    formats: ["image/avif", "image/webp"],
  },
}
```

Always `next/image` over `<img>`. `fill` requires a positioned parent, and
always pass `sizes`.

## Other removals and defaults

- **Turbopack is the default bundler** for `dev` and `build`. Turbopack config
  moved location; check the upgrade guide before adding bundler config.
- **`next lint` is removed.** Run `eslint` directly. ESLint now uses flat
  config (`eslint.config.mjs`).
- `middleware` was renamed to `proxy`.
- AMP support, runtime configuration and `experimental.dynamicIO` are gone.
- Parallel routes now require `default.js`.
- React 19.2; the App Router pins its own React canary.

## The server/client boundary trap

This one costs an afternoon because **the build stays green**.

A *value* exported from a `"use client"` module and imported by a Server
Component does not arrive as the value. It arrives as a client module
reference. Spreading it yields an object with `undefined` fields, and the page
throws at runtime:

```
Cannot read properties of undefined (reading 'length')
```

```tsx
// ❌ catalog-filters.tsx is "use client"
import { EMPTY_FILTERS } from "@/components/storefront/catalog-filters"
const filters = { ...EMPTY_FILTERS, collections }   // fields are undefined

// ✅ plain module, safe on both sides
import { EMPTY_FILTERS } from "@/lib/filters"
```

**Rule:** shared constants and types that a Server Component needs live in a
plain module under `lib/`, never beside the client component that also uses
them. Types alone are erased and would be fine — but do not rely on that
distinction; keep both in `lib/`.

## Tailwind v4

No `tailwind.config.js`. Configuration is CSS:

```css
@import "tailwindcss";
@theme inline { --color-primary: var(--primary); }
```

`postcss.config.mjs` needs `"@tailwindcss/postcss": {}`.

## The gate

```bash
npx tsc --noEmit
npm run build
```

A green build is necessary but not sufficient on a design-led project. Run
`npm run dev` and look at the page before claiming it works.
